# Инструкция по установке DLE Social AutoPost

Плагин предназначен для автоматической публикации новостей и пресс-релизов с сайта на базе **DataLife Engine (DLE 13.0 — 21.0)** в канал **Telegram** и сообщество **ВКонтакте**.

---

## Способ 1: Автоматическая установка через панель управления (Рекомендуется)

Данный способ использует штатную систему плагинов DLE и не требует ручной правки файлов скрипта.

1. Перейдите в панель управления DLE: `Панель управления -> Управление плагинами`.
2. Нажмите кнопку **«Загрузить плагин»**.
3. Выберите собранный архив `dist/dle-social-autopost-v1.1.0.zip` (или скачайте готовый релиз).
4. DLE автоматически распакует файлы в необходимые каталоги (`engine/classes/autopost/`, `engine/inc/`, `cron/`) и применит виртуальные модификации.
5. При успешной установке в боковом меню админпанели в разделе «Сторонние модули» появится раздел **«Автопостинг VK & Telegram»**.
6. Перейдите в раздел модуля и настройте параметры доступа к Telegram и ВКонтакте.

---

## Способ 2: Ручная установка через XML и FTP

Если у вас отключена загрузка архивов или ограничен доступ к FTP из PHP:

1. Скопируйте файлы из каталога репозитория на ваш сервер:
   - Папку `engine/classes/autopost/` скопируйте в `engine/classes/autopost/`
   - Файл `engine/inc/autopost.php` скопируйте в `engine/inc/`
   - Иконку `engine/skins/images/autopost.png` скопируйте в `engine/skins/images/`
   - Скрипт `cron/autopost.php` скопируйте в папку `cron/` в корне вашего сайта.
2. Убедитесь, что каталог `engine/data/` доступен для записи (права `chmod 775` или `chmod 777`), чтобы плагин мог сохранять файл настроек `engine/data/autopost.php`.
3. В админпанели DLE перейдите в `Управление плагинами` -> `Загрузить плагин`.
4. Выберите файл `plugin.xml` (или `dist/dle-social-autopost.xml`).
5. Плагин создаст необходимые таблицы в базе данных и активирует хуки.

---

## Структура базы данных

Плагин создает две таблицы в MySQL (с префиксом вашей базы данных, по умолчанию `dle_`):

### 1. `{prefix}_autopost_queue`
Очередь отложенных публикаций и задач для повторной отправки:
- `id` — идентификатор задачи;
- `news_id` — ID новости в DLE;
- `target` — целевой канал (`all`, `telegram`, `vk`);
- `status` — текущий статус (`pending`, `processing`, `failed`, `done`);
- `attempts` — число совершенных попыток;
- `error_message` — текст последней ошибки;
- `created_at` / `updated_at` — временные метки.

### 2. `{prefix}_autopost_log`
История всех отправленных постов:
- `id` — идентификатор записи;
- `news_id` — ID опубликованной новости;
- `channel` — соцсеть (`telegram` или `vk`);
- `remote_id` — ID сообщения в Telegram или ID поста ВКонтакте;
- `status` — результат (`success` или `error`);
- `error_message` — текст ошибки API при сбое;
- `post_date` — дата и время публикации.

## Обновление плагина

Для обновления плагина:
1. Загрузите новую версию архива или XML в разделе `Управление плагинами` поверх существующего.
2. Все настройки и история публикаций сохраняются.

---

## Удаление плагина

При удалении плагина через штатный менеджер плагинов DLE:
- Автоматически удаляются все скопированные файлы плагина (`engine/classes/autopost/*`, `engine/inc/autopost.php`, `cron/autopost.php`, `engine/skins/images/autopost.png`) благодаря тегам `<filedelete>1</filedelete>` и `<filelist>`;
- Хук `<phpuninstall>` удаляет файл настроек `engine/data/autopost.php` и директорию `engine/classes/autopost/`;
- Хук `<mysqldelete>` очищает таблицы очереди и логов (`dle_autopost_queue`, `dle_autopost_log`);
- Удаляются виртуальные хуки в файлах добавления и редактирования новостей и меню админпанели.
